# Проверка кешей — 16 сентября 2026

Проверены кеши слоя данных, сохранённые состояния экранов, обработчики плеера, загрузки и Cast receiver. Основа проверки — Repowise, анализ владельцев данных и путей обновления, тесты с задержанными ответами, локальным HTTP-сервером и Android-эмулятором. Изменения выполнены поверх `c7cc04c`.

## Найдено и исправлено

| Область | Ошибка | Исправление |
| --- | --- | --- |
| OP/ED | Старый lifecycle мог снять обработчик кнопок с уже перепривязанного плеера; быстрый путь кешированного контроллера его не восстанавливал | Очистка принадлежит привязке представления; повторная привязка проверяет skip-сессию. Автоматическое скрытие после READY сохраняет предложение пропуска |
| Плеер | При неизменном URL listener сохранял старые callbacks и данные следующей серии | Актуальная привязка хранится отдельно для каждой идентичности воспроизведения; закрытие старой серии использует её последние callbacks |
| Экраны | После выхода из аккаунта сохранённая карточка могла снова попасть в очищенный кеш; офлайн-карточка восстанавливалась после возвращения сети | Снимки содержат аккаунт, ревизию сессии, язык и режим сети; несовместимые состояния не сохраняются и не восстанавливаются |
| Язык и загрузка экранов | Флаги «уже загружено» и поздние ответы могли оставлять прежний язык | Сброс состояний и проверка контекста перед публикацией каталога, расписания, карточки и дополнительных данных |
| Ручное обновление | Повторная загрузка экрана могла сразу вернуть прежний ответ из дискового кеша | Перед обновлением сбрасываются API-снимки и их поколение, затем кеши экранов. Скачанные видео, субтитры и история этим действием не очищаются |
| История | Полный или поанимешный ответ сервера мог затереть новый прогресс либо восстановить сброшенный просмотр | Атомарная проверка ревизии хранилища перед заменой; проверка той же ревизии перед публикацией в UI и профильный кеш |
| Список видео | `anime_with_videos` и `videos` могли содержать разные поколения списка | Общая блокировка пары; комбинированный ответ обновляет оба представления, отдельный список инвалидирует старый комбинированный снимок |
| Качество источника | Ключ отбрасывал query и регистр пути, не проверял серию/озвучку/плеер | Сохраняются значимые части URL; проверяются метаданные источника. Изменение URL может чаще вызывать повторное определение качества |
| Субтитры | Уже полученный новый текст игнорировался при наличии файла для того же URL | Свежий загруженный или перехваченный текст заменяет прежнее содержимое, с сохранением защиты от записи после очистки |
| Частичные загрузки | Докачка ориентировалась только на длину `.part`, позволяя склеить разные файлы | Сохраняются хеш идентичности запроса, сильный ETag и конечный URL; используется If-Range. Несовпадение или отсутствие надёжного валидатора приводит к загрузке заново |
| Chromecast | Новый media без метаданных приложения наследовал сведения предыдущей серии | Предыдущие сведения сохраняются только при отсутствии самого media после завершения, но сбрасываются при появлении другого media |
| Compose | Кеш подписи скачанного качества не учитывал перевод; структура фокуса карточки не учитывала статус аниме | Добавлены недостающие зависимости `downloaded` и `details.status` |

Основные файлы: `LocalStorage.kt`, `RepositoryData.kt`, `SubtitleTracks.kt`, `DirectDownloads.kt`, `AppState.kt`, `AuthStateRuntime.kt`, `AnimeDetails.kt`, `BrowseRuntime.kt`, `WatchHistory.kt`, `YummyDroidRuntime.kt`, `NativePlayer.kt`, `PlayerControls.kt`, `DetailsContent.kt`, `cast-receiver/receiver.js`.

## Проверки

- Все unit-тесты модулей `app` и `data`: 878 + 290, без ошибок; `:app:testDebugUnitTest :data:testDebugUnitTest --offline --no-configuration-cache`. Debug APK и APK инструментальных тестов собираются успешно.
- JavaScript: 17 тестов Cast receiver.
- Android API 36: 5 тестов `PlayerSkipVisibilityTest` и `NativePlayerLifecycleCacheTest`, включая исчезнувшую skip-сессию при живом таймлайне и обновление callbacks без смены URL.
- Новые HTTP-регрессии проверяют ETag, If-Range, 206/416, смену URL, заголовков и redirect при докачке.
- Новые проверки задержанных ответов покрывают смену языка/контекста, ручное обновление и сохранение/сброс истории во время запроса.

Проверка покрывает обнаруженные в проекте механизмы и перечисленные сценарии. Изменения содержимого внешних провайдеров по неизменному URL в пределах обычного TTL остаются частью принятой политики кеширования; ручное обновление API-данных теперь обходит этот срок.
