# Загрузка карточки аниме

Проверка 17 сентября 2026 года после 1.4.61. Запросов к сайту и источникам
для этой проверки не выполнялось; использованы локальные тесты.

## Что блокирует показ

Основные данные и варианты видео приходят одним запросом `/anime/{id}?need_videos=true`.
При открытии карточки приложение не проверяет медиассылки всех источников.
Полноэкранная загрузка зависит от `details`; комментарии, рекомендации и
история не являются условием показа основной карточки. Согласование личной
оценки использует локальное состояние, а не дополнительный сетевой запрос.

## Исправления

1. Восстановление профиля могло изменить контекст уже открытой карточки,
   сбросить её в Loading и сделать ответ старого запроса неактуальным.
   Повторно запускался только каталог на Home. Теперь при изменении контекста
   перезапускается загрузка видимой карточки. Проверка того же профиля не
   создаёт лишнего запроса; переход пользователя на другой экран сохраняется.
   Для уведомления со ссылкой-alias и ещё неизвестным числовым ID сохраняется
   исходная цель открытия. Старый ответ не может стереть alias новой карточки.

2. Даже для аниме без скачанных серий чтение offline-данных разбирало общий
   `index.json` со всеми карточками. Сохранение после API снова читало и
   переписывало его, добавляя туда онлайн-карточки без загрузок. Теперь сначала
   проверяется реестр загрузок выбранного аниме. Если зарегистрированных
   завершённых файлов нет, общий индекс не читается и не переписывается.
   Онлайн-метаданные остаются в отдельном content cache. Для настоящих загрузок
   сохраняются обновление карточки, нейтральность относительно аккаунта и
   синхронизация с регистрацией файлов. Старый индекс автоматически не удаляется.

Второй путь существовал и до последних изменений плеера. Его вклад в задержку
конкретного ТВ не измерен; исправление убирает подтверждённую лишнюю работу,
но не устанавливает скорость API или накопителя устройства.

## Проверка

Новый тест сохранения онлайн-карточки падал до исправления: создавался общий
offline-индекс. После исправления он не создаётся, а существующий индекс
других карточек не меняется. Зарегистрированные файлы остаются доступны после
обновления метаданных через другой экземпляр хранилища; незарегистрированные
файлы не удаляются и, как раньше, не считаются готовыми загрузками.

Для смены профиля проверяются ответ до и после смены контекста, отсутствие
повторного запроса при неизменном ID и уход на Home. Тесты вызывают production
helper и координатор операций; весь AuthStateRuntime с настоящим API и ТВ
этими тестами не моделируется.

Полный набор вместе с изменениями диагностики и восстановления CVH: 1318 тестов
без ошибок и пропусков, debug-сборка и компиляция release/instrumentation успешны.

## Фоновая запись кэша — 20 сентября 2026

Повторный симптом: полноэкранный индикатор до появления любых данных. Три
гостевых запроса `/anime/{id}?need_videos=true` с рабочего компьютера
(10818, 24920, 1486) вернули HTTP 200 за 0,326 / 0,316 / 0,267 секунды.
Это не замер сети или накопителя устройства пользователя.

Проверены места записи кэша и вызовы из загрузки экранов/плеера:

- Карточки, списки видео, каталог, поиск, фильтры и расписание теперь сразу
  публикуются в памяти. JSON и файловые записи выполняет последовательная
  очередь `CacheDiskWriter`, без удержания блокировок памяти/аккаунта/контекста.
- Кэш качества источников сохраняет неизменяемый снимок карты через ту же
  очередь; начало воспроизведения не ожидает его записи.
- Справочные данные аниме для истории доступны в памяти сразу. JSON кодируется
  в очереди, после чего SharedPreferences.apply сохраняет данные. Очистка
  отменяет ожидающие старые записи.
- Обновление метаданных скачанного аниме запускается через существующую
  cacheMaintenanceOperations после публикации Ready. Ошибка сохранения
  не скрывает карточку и не отменяет UI scope.
- SiteDomainResolver хранит состояние только в памяти. Coil загружает
  изображения независимо от Ready карточки. Файл субтитров должен существовать
  до передачи локального URI плееру: его создание остаётся ожидаемым.
- Авторизация, настройки, прогресс просмотра и реестр скачанных файлов —
  сохраняемые пользовательские данные, их контракт не заменён кэшем.

Очередь учитывает ожидающие значения и удаления combined-снимков. Очистка
упорядочена с уже начатыми записями; устаревшие задания пропускаются. Ошибка
диска не отменяет успешную загрузку и не разрешает чтение старого снимка.
Явная команда очистки ожидает очередь перед пересчётом размера.

Границы: при остановке процесса последняя запись восстанавливаемого кэша
может не завершиться. Чтение с диска и проверка скачанных файлов остаются
частью загрузки. Офлайн-индекс сохраняет прежние блокировки целостности:
его фоновое обновление может конкурировать с другими офлайн-операциями и
захватом контекста. Полное отсутствие задержек IO и измеренное ускорение
конкретного ТВ этим изменением не утверждаются; устройство не подключено.

### Повторное использование после перезапуска

Обычный запуск и восстановление профиля не очищают файловый кэш. Карточки
читаются с диска до запроса API, при совпадении языка/аккаунта и возрасте
до 30 минут. Тест сохраняет десять карточек, переносит только файлы в новый
каталог без общего CacheState и повторно загружает карточки и списки видео:
счётчик HTTP остаётся равным десяти первоначальным запросам.

Дублирование устранено: saveAnimeWithVideos сохраняет один combined-снимок,
а readVideos использует его при отсутствии отдельного videos-снимка. Старый
конкурирующий снимок удаляется раньше записи нового.

Оставшийся источник потери полезного кэша: mutateAccountContent сбрасывает
все карточки/видео/каталог/поиск до и после изменения списка, избранного,
оценки или подписки. Обычное сохранение прогресса просмотра этого не делает.
Текущая защита персонализированных ответов сохранена; точечная инвалидация
потребует отдельно связать изменённое аниме с ключами кэша и фильтрами каталога.

Проверка изменений: 382 теста data и 63 выбранных теста app прошли, debug APK
собран. В общем прогоне упал BufferedRetryIntegrationTest:
allohaMp4KeepsHealthyQueueAcrossFourForbiddenResumeResponses (строка 146);
этот тест не использует изменённые кэши. Общий прогон остановлен во время
длительных RealTimeBufferingIntegrationTest, полный набор не считается прошедшим.
