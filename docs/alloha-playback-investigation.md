# Alloha: обрывы воспроизведения и лишние запросы

Проверка кода: 2026-09-16. Запросы к реальным источникам и нагрузочные проверки не выполнялись.

## Найдено и исправлено

- Нативный плеер использовал `defaultVideoResolveClient` с `callTimeout = 20 s`.
  Этот таймаут включает чтение всего тела ответа, даже когда плеер временно не
  читает его из-за заполненного буфера. Для воспроизведения выделен клиент без
  общего дедлайна, с прежними ограничениями подключения (8 s) и чтения (20 s).
  Это устраняет искусственный повод для повторного открытия живого потока.
- Media3 использовал стандартные повторы и переключение дорожек/адресов;
  поверх них `NativePlayer` перебирал до трёх запасных ссылок после HTTP-ошибки.
  Теперь HTTP 403/429 запрещают оба вида автоматического восстановления внутри
  источника. Остальные ошибки сохраняют прежнее поведение.
- Сбор метаданных мог повторно открыть скрытый Alloha WebView уже после запуска
  нативного видео. Первое открытие теперь завершает поиск субтитров и обработку
  метаданных; результат помечается как обработанный и используется повторно.
  WebView уничтожается до передачи результата плееру. Цена — возможное увеличение
  начального ожидания, в том числе до четырёх секунд ожидания отсутствующих субтитров.
- Получение ссылок теперь прекращает текущую сессию при 403/429, включая запросы
  WebView и обработку субтитров. CVH не запускает после этого WebView-fallback,
  а перебор доменов сайта не продолжается. Существующая пауза загрузок дополнена 429.
- При окончательной ошибке позиция сохраняется в маршруте плеера, откуда её берут
  повторный запуск и ручной выбор источника.
- Для окна ошибки добавлен переход фокуса между Compose-кнопкой «Повторить» и
  нативными элементами плеера, с обратным переходом и сохранением прокрутки текста.
- Закрытие плавающей подсказки OP/ED кнопкой «Смотреть» больше не возвращает
  полную панель перед её анимацией скрытия: подсказка закрывается сразу.

## Что установлено для других источников

Исправления HTTP-клиента и Media3 относятся ко всем источникам нативного плеера.
Alloha, Kodik, Aksor, Sibnet и CVH уже пропускают лишнюю проверку медиассылки;
добавлять её не потребовалось. Автоматический выбор другого источника исключает
неудавшийся источник; ручная кнопка «Повторить» остаётся явной попыткой пользователя.

Общий поиск качеств/кандидатов всё ещё может разрешать несколько источников
параллельно. Глобальный лимит запросов, общий кеш подписанных ссылок и обработка
`Retry-After` в этой правке не добавлены. Лимиты сервера Alloha неизвестны.
Без журнала реального сбоя нельзя доказать, что любой 403 вызван именно частотой
запросов: недействительная ссылка или серверное ограничение тоже возможны.

## Проверка без источников

Пройдено 123 целевых модульных теста; debug APK и instrumentation-тесты собраны.

- Локальный MockWebServer: продолжение одного ответа после прежнего 20-секундного
  дедлайна, без второго запроса; настройки таймаутов и TLS-проверки клиентов.
- Подставные HTTP-ответы: 403/429 останавливают разрешение CVH/обычного iframe
  после одного запроса, без WebView и смены домена; последующие запросы сессии отклоняются локально.
- Модульные тесты Media3 policy: отсутствие повторов/смены дорожек и адресов
  при прямых и вложенных 403/429; обычное восстановление для прочих ошибок.
- Модульные тесты: повторный сбор завершённых метаданных не обращается к сети;
  терминальная ошибка и последующий выбор источника сохраняют позицию.
- Проверки навигации полного окна ошибки добавлены в Android instrumentation.
  Запуск эмулятора заблокирован политикой окружения; выполнение этих UI-тестов
  на устройстве остаётся непроверенным.

Семантика библиотек сверена с исходниками используемых версий:
[OkHttp 4.12.0](https://github.com/square/okhttp/blob/parent-4.12.0/okhttp/src/main/kotlin/okhttp3/OkHttpClient.kt),
[Media3 1.10.1](https://github.com/androidx/media/blob/1.10.1/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/upstream/DefaultLoadErrorHandlingPolicy.java).
